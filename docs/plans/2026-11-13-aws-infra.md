### 1-2. dev/prod 분리 방식 (디렉터리 · nginx · 포트 · systemd)
```
/srv/meta-gallery/
  prod/releases/<git-sha>/     ← 배포 단위(불변)
  prod/current -> releases/<git-sha>   ← 심볼릭 링크 교체로 무중단 전환
  prod/shared/
  dev/releases/<git-sha>/
  dev/current -> releases/<git-sha>
  dev/shared/
/etc/meta-gallery/prod.env     ← 0600 root:root (DB 접속정보 등)
/etc/meta-gallery/dev.env      ← 0600 root:root
/var/log/nginx/meta-gallery-{prod,dev}.{access,error}.log
/var/backups/meta-gallery/     ← pg_dump 로컬 보관
```
| 구분 | 운영계(prod) | 개발계(dev) |
|---|---|---|
| nginx `server_name` | `metagallery.duckdns.org` | `metagallery-dev.duckdns.org` |
| nginx 설정 파일 | `/etc/nginx/sites-available/meta-gallery-prod.conf` | `.../meta-gallery-dev.conf` |
| 정적 루트 | `/srv/meta-gallery/prod/current` | `/srv/meta-gallery/dev/current` |
| 향후 백엔드 포트 | `127.0.0.1:3000` (루프백 전용) | `127.0.0.1:3001` (루프백 전용) |
| systemd 유닛 | `meta-gallery-api@prod.service` | `meta-gallery-api@dev.service` |
| DB / 롤 | `metagallery_prod` / `mg_prod` | `metagallery_dev` / `mg_dev` |
| 헬스체크 경로 | `/healthz` (nginx가 200 직접 반환) | `/healthz` |
| 개발계 접근 제한 | - | HTTP Basic 인증 + `noindex` 헤더 (정보보호팀 검토 대상) |

- 외부 노출은 nginx(80/443)만. 백엔드와 PostgreSQL은 루프백에만 바인딩한다.
- systemd는 템플릿 유닛 `meta-gallery-api@.service` 하나로 두고 `%i`로 prod/dev를 구분, `EnvironmentFile=/etc/meta-gallery/%i.env`를 읽는다.
- **백엔드 코드가 없으므로 유닛은 "설치만 하고 enable하지 않는" 템플릿 상태로 납품한다.** 정적 서비스는 백엔드 없이도 동작한다.
- 배포 계정 `deploy`(그룹 `mgweb`)가 `/srv/meta-gallery`를 소유한다. `deploy`에게는 심볼릭 링크 교체와 `systemctl reload nginx`에 한정한 sudoers 규칙만 준다.

### 1-3. DuckDNS 서브도메인과 HTTPS
- 서브도메인 2개를 쓴다(DuckDNS 무료 계정은 계정당 최대 5개).
  - 운영계: `metagallery.duckdns.org` (DuckDNS 서브도메인 이름 `metagallery`)
  - 개발계: `metagallery-dev.duckdns.org` (DuckDNS 서브도메인 이름 `metagallery-dev`)
  - **변경 사유: 2026-11-13 CEO가 DuckDNS에 `metagallery`로 발급. 하이픈 없는 쪽이 실제 값이다.**
    최초 계획값은 `meta-gallery` / `meta-gallery-dev`(하이픈 있음)였으나 발급값이 사실이므로 코드를 거기에 맞췄다.
    바뀐 것은 **`.duckdns.org` 호스트명과 DuckDNS 서브도메인 이름뿐**이다. 인스턴스·고정 IP 이름(`meta-gallery-app`,
    `meta-gallery-ip`), S3 버킷, 서버 경로(`/srv/meta-gallery/`, `/etc/meta-gallery/`), systemd 유닛,
    nginx 설정 파일명, certbot `--cert-name`, DB·롤 이름은 **그대로**다.
- 두 서브도메인 모두 같은 Lightsail 고정 IP를 가리킨다. 분기는 nginx `server_name`이 한다.
- 고정 IP라 갱신이 필요 없지만, DuckDNS는 장기 미갱신 도메인을 회수하므로 **5분 주기 systemd timer로 keepalive** 갱신을 돈다. 토큰은 `/etc/meta-gallery/duckdns.env`(0600)에 둔다.
- HTTPS는 Let's Encrypt + certbot, **HTTP-01(webroot) 방식**. 80 포트가 열려 있고 공인 IP가 있어 DNS-01이 필요 없다.
  - 환경별로 인증서를 따로 발급한다(갱신 실패가 서로 번지지 않게).

- **ACME 고정값 (2026-11-13 검수 중 팀장 확정. 최초 계획에 없어 팀원3·팀원4가 각자 정했다가 어긋난 값이다.)**

| 항목 | 확정값 | 비고 |
|---|---|---|
| ACME HTTP-01 webroot | `/var/www/certbot` | 0755 `root:www-data`. nginx는 `location ^~ /.well-known/acme-challenge/ { root /var/www/certbot; }`로 받는다(`alias` 아님). `provision.sh`가 `.well-known/acme-challenge`까지 만든다. |
| certbot 인증서 이름 | 운영계 `meta-gallery-prod` / 개발계 `meta-gallery-dev` | `certbot --cert-name` 값 |
| 인증서 디렉터리 | `/etc/letsencrypt/live/meta-gallery-prod/`, `/etc/letsencrypt/live/meta-gallery-dev/` | **호스트명 디렉터리가 아니다.** `--cert-name`을 주면 certbot이 호스트명 대신 이 이름을 쓴다. nginx `ssl_certificate`를 `metagallery.duckdns.org`로 쓰면 HTTPS가 뜨지 않는다. |

  - 확정 근거: 발급 스크립트(`scripts/ops/issue-certificates.sh`)가 이 값의 단일 출처다. 반대 방향(호스트명 기준)으로 통일하면 스크립트의 `--cert-name`·`WEBROOT`와 문서 2건을 고쳐야 하고, 환경별 분리 발급 의도도 이름에서 드러나지 않는다.
  - 이 값을 바꾸려면 **nginx 설정 2개 + `provision.sh`의 `ACME_WEBROOT` + `issue-certificates.sh` + `docs/infra/server-layout.md` 5장 + `docs/infra/domain-and-https.md`를 한꺼번에** 고친다.
  - 발급 전 `--dry-run`(staging)으로 먼저 확인한다. `*.duckdns.org`는 Public Suffix List에 등록돼 있어 서브도메인별 발급 한도가 독립적이다.
  - 갱신은 certbot 패키지의 systemd timer에 맡기고, `--deploy-hook`으로 `systemctl reload nginx`를 건다.
- 인증서 발급은 실제 도메인·서버가 있어야 하므로 이번 단계 산출물은 **발급 절차 문서 + 실행 스크립트**까지다.

### 1-4. S3 사용 용도
| 버킷(제안) | 용도 | 공개 범위 |
|---|---|---|
| `<ASSETS_BUCKET_PROD>` | 운영계 작품 이미지·텍스처·3D 에셋 | 1단계 **완전 비공개** |
| `<ASSETS_BUCKET_DEV>` | 개발계 에셋(운영 데이터 복사 금지) | 완전 비공개 |
| `<BACKUPS_BUCKET>` | PostgreSQL `pg_dump`, nginx 로그 아카이브, 릴리스 artifact | 완전 비공개(영구) |

- 공통 설정: Block Public Access 4개 항목 **모두 ON**, 버전 관리 ON, 기본 암호화 SSE-S3(AES256), `aws:SecureTransport=false` 거부 정책.
- 수명주기: 에셋 버킷 = 이전 버전 30일 후 삭제 / 백업 버킷 = 30일 후 Glacier Instant Retrieval, 180일 후 삭제.
- 버킷 이름은 전역 유일해야 한다. 위 이름이 선점돼 있으면 `-2`를 붙이지 말고 계정 ID 4자리를 접미사로 쓴다(문서에 규칙 명시).
- **퍼블릭 접근 방향(인프라팀 권고)**: 버킷을 공개로 열지 않는다. 지금은 에셋이 HTML에 인라인돼 있어 공개 버킷이 필요 없다. 공개 전달이 필요해지면 버킷 공개가 아니라 **CloudFront + OAC(Origin Access Control)** 로 간다. → 최종 선택은 CEO 결정 필요(5장).

### 1-5. PostgreSQL (인스턴스 내 직접 설치)
- Ubuntu 24.04 기본 저장소의 PostgreSQL 16을 설치한다(PGDG 저장소 추가 불필요).
- `listen_addresses = 'localhost'`, 포트 5432. 외부 노출 없음. Lightsail 방화벽에 5432를 열지 않는다.
- `pg_hba.conf`: `local`은 peer, `127.0.0.1/32`는 `scram-sha-256`. 롤 2개는 **각자 DB만** 접근(`CONNECT` 권한 교차 부여 금지, `public` 스키마 `CREATE` 회수).
- 접속 문자열은 `/etc/meta-gallery/{prod,dev}.env`의 `DATABASE_URL`로만 전달한다. 저장소에 비밀번호를 커밋하지 않는다(`.env.example`만 커밋).
- 백업: 매일 03:10 KST systemd timer → `pg_dump -Fc` → `/var/backups/meta-gallery/<env>/` 보관 7일 → `aws s3 cp`로 `s3://<BACKUPS_BUCKET>/postgres/<env>/YYYY/MM/DD/`. 복구 절차(`pg_restore`)도 문서에 적는다.
- 추가로 Lightsail 자동 스냅샷(일 1회)을 켜서 인스턴스 전체를 보호한다.
  - **스냅샷 시각 고정값(2026-11-13 검수 중 팀장 확정): `19:00` UTC = 04:00 KST.** 팀원2가 제안한 18:00 UTC(03:00 KST)는 pg_dump(03:10 KST, 타이머 `RandomizedDelaySec=120`까지 더하면 최대 03:12)와 10분 간격이라 burst 인스턴스에서 디스크 I/O가 겹칠 수 있었다. pg_dump **뒤**로 50분 미뤄서 ① I/O 경합을 피하고 ② 스냅샷이 그날 생성된 로컬 덤프까지 포함하게 한다.
- **스키마가 담을 데이터 범위(테이블·컬럼 설계)는 백엔드팀 협조 사항이다.** 인프라팀은 DB·롤·권한·백업·접속 경로까지만 정의하고, 테이블 생성은 백엔드팀 마이그레이션에 맡긴다.

### 1-6. git 저장소와 배포 파이프라인
- `git init -b main` → 최초 커밋 → `dev` 브랜치 분기. 두 브랜치 모두 보호(직접 push 금지, PR 필수).
- 흐름: `feature/*` → PR → `dev`(머지 시 개발계 자동 배포) → PR → `main`(머지 시 운영계 배포).
- 운영계 배포는 GitHub Environment `prod`에 **수동 승인(required reviewer)** 을 걸 것을 권고한다(CEO 결정 필요).
- 워크플로 3개:
  - `ci.yml`: PR·push 공통. `build-standalone.py` 실행 성공, 산출물 비어 있지 않음, three.js r128 CDN 참조 유지 확인, 셸 스크립트 `shellcheck`, `terraform fmt -check`, 평문 비밀값 패턴 검사.
  - `deploy-dev.yml`: `dev` push → 빌드 → SSH로 `releases/<sha>` 업로드 → `current` 심링크 교체 → `/healthz` 200 확인(실패 시 이전 릴리스로 되돌림).
  - `deploy-prod.yml`: `main` push → 동일 절차 + 승인 게이트.
- 필요한 GitHub Secrets/Variables(값 입력은 CEO): `LIGHTSAIL_HOST`, `LIGHTSAIL_SSH_KEY`, `LIGHTSAIL_SSH_USER`, `DUCKDNS_TOKEN`, (S3 연동 시) AWS OIDC 역할 ARN. 환경별로 GitHub Environments `dev`/`prod`에 분리 저장.
- `.gitignore`에 `dist/`를 넣는다(빌드 산출물, CI가 생성). 로컬 확인은 기존대로 `python3 scripts/build-standalone.py`로 만든다.
- **GitHub 원격 저장소는 만들지 않는다.** 저장소 생성·시크릿 입력 절차만 문서로 남기고 CEO 결정으로 넘긴다.

### 1-7. 모니터링 계획
- Lightsail 기본 지표 알람: CPU 사용률(burst 소진), 네트워크 전송량(**1TB 한도 대비 80%** — `micro_3_2`의 포함 전송량은 1TB다), 인스턴스 상태.

- nginx 로그는 logrotate 14일 보관 후 백업 버킷으로 아카이브.

## 4. 리스크
- **조직 SCP로 서울 리전을 쓸 수 없어 시드니(`ap-southeast-2`)를 쓴다 → 한국에서 지연 약 130~150ms다.** 정적 에셋 1회 로드 위주인 현 목업에는 감수 가능하지만, **향후 실시간 멀티플레이·채팅을 넣으면 체감 지연이 문제가 되어 리전·아키텍처 재검토가 필요하다.** SCP는 관리계정(`<AWS_ORG_MANAGEMENT_ACCOUNT_ID>`)에서만 바꿀 수 있고, 예외 요청안은 2026-11-13 CEO 결정으로 기각됐다.
- **AWS 무료 플랜 크레딧에는 만료일이 있다.** 그때까지는 크레딧에서 차감되어 실지출이 $0이지만, 만료 후에는 **유료 플랜 전환 또는 자원 중단** 결정이 필요하다. 만료 2~3개월 전에 CEO 안건으로 올린다.
- **이 AWS 계정(`<AWS_ACCOUNT_ID>`)은 다른 사내 프로젝트와 공유한다.** 청구서·IAM 권한·SCP 적용 범위가 함께 묶여 있어, 한쪽 프로젝트의 비용 증가나 권한 변경이 다른 쪽에 영향을 준다. 자원 태그(`Project=meta-gallery`)로 구분하고, 계정 분리가 필요해지면 CEO 결정으로 올린다.
- AWS 자격증명이 없어 `terraform plan`과 S3·Lightsail 실제 검증을 **이번 단계에서 할 수 없다.** 문법 검사까지만 하고, 적용 시 오류 가능성을 남긴다. `terraform validate`도 프로바이더 다운로드가 필요해 실패할 수 있다(실패 시 "확인하지 못함"으로 기록).
- 인스턴스 1대 공유라 개발계 부하·장애가 운영계에 번질 수 있다. 1GB RAM에 PostgreSQL + 향후 Node 2개는 빡빡하다 → swap 2GB와 메모리 감시로 완화하고, 한계가 보이면 bundle 상향을 CEO에게 올린다.
- DuckDNS는 무료 서비스로 SLA가 없다. 장애 시 도메인 접속이 끊긴다(고정 IP 직접 접속으로 임시 대응).
- ~~`meta-gallery`·`meta-gallery-dev` 서브도메인이 이미 선점됐을 수 있다.~~ → **2026-11-13 해소(운영계)**: CEO가 `metagallery`로 발급. 개발계 `metagallery-dev` 등록 여부는 확인하지 못함. 대체 이름 규칙은 `infra/duckdns/README.md` 7절.
- 백엔드 코드가 없어 systemd 유닛·DB 스키마는 템플릿 상태다. 백엔드팀 산출물이 나오면 재작업이 필요하다.
- GitHub 원격 저장소가 없어 Actions 워크플로는 **실제 실행 검증을 하지 못한다.**
